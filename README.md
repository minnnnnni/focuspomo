# FocusPomo

**산만함·졸음 인식 기반 집중 관리 뽀모도로 타이머** — 캡스톤 디자인 프로젝트

웹캠으로 자리 이탈·졸음·눈 깜빡임을 측정하고, 활성 창(앱 이름·브라우저 도메인)을 함께 기록해 집중 세션(기본 25분)이 끝날 때마다 **집중도 점수와 리포트**를 보여주는 Windows 데스크톱 앱입니다.

> 🚧 현재 개발 중입니다 (5주차: 스키마·설정 합의 및 레포 세팅 단계).

---

## 핵심 아이디어

- **세션 중 무개입** — 집중 세션 동안은 알림을 주지 않고 기록만 합니다. 신호 판정이 일부 틀려도 작업 흐름을 방해하지 않습니다. 사용자가 직접 일시정지할 수는 있고, 정지한 구간은 점수에서 뺍니다.
- **세션 후 리포트** — 짧은 휴식(기본 5분)이 시작될 때 방금 세션의 집중도(0~100점), 집중·딴짓·자리비움·졸음 시간, 10초 슬롯별 태그, 한 줄 요약을 보여줍니다.
- **웹캠 + 앱 사용 맥락** — 얼굴·눈 신호만으로는 잡을 수 없는 "화면은 보고 있지만 유튜브를 보는" 딴짓까지 반영합니다.
- **점수는 코드가 계산** — 점수는 "판정된 시간 중 집중한 시간의 비율"로 결정론적으로 계산합니다. LLM은 창 분류(작업/딴짓/미분류)와 리포트 문구만 담당합니다.
- **세션 길이 설정** — 위쪽 내비게이션 바의 "설정"에서 집중 시간, 짧은·긴 휴식 시간, 긴 휴식 주기(몇 세션마다)를 바꿀 수 있습니다 (기본 25분 / 5분 / 15분 / 4세션, `data/settings.json`에 저장).
- **영상은 로컬에서만** — 웹캠 영상·프레임은 저장하거나 전송하지 않습니다.

## 동작 흐름

```
[세션 시작]
   ↓
[캘리브레이션] 5초 화면 응시 → 개인별 눈 크기 기준값(ear_baseline)
   ↓
[집중 세션, 기본 25분]  (개입 없이 기록만, 사용자가 일시정지 가능)
   ├─ CV 스레드   : 웹캠 ~15fps → 1초 요약 → 10초 슬롯으로 압축
   ├─ 창 스레드   : 1초마다 활성 창(앱 이름·도메인)·백그라운드 재생 조회 → 10초 슬롯 (명확한 딴짓 우선)
   └─ GUI 스레드  : 두 메시지를 slot 번호로 병합 → 슬롯 로그(10초 슬롯, 25분이면 150개), 정지 구간 기록
   ↓
[세션 종료]
   ├─ 정지 구간과 겹친 슬롯 제외
   ├─ LLM API → 세션에 나온 창 목록 분류 + 리포트 문구
   └─ 코드 → 슬롯마다 태그 하나 → 10초 이탈 보정 → 집중 비율(0~100점)
   ↓
[짧은 휴식 + 집중도 리포트] → N세션마다 긴 휴식 (기본 4)
```

단일 프로세스·멀티스레드 구조이며, CV·창 스레드는 하나의 큐(`slot_queue`)로 GUI에 10초 슬롯 단위 메시지를 보냅니다.

### 판정 신호

10초 슬롯마다 태그 하나를 위에서부터 처음 해당하는 것으로 붙입니다.

| 태그     | 판정 방법                                                                                          | 점수       |
| -------- | -------------------------------------------------------------------------------------------------- | ---------- |
| 판정불가 | 슬롯 동안 카메라 기록이 없음                                                                       | 분모 제외  |
| 자리비움 | 10초 슬롯 중 얼굴이 검출된 초가 절반 미만                                                          | 이탈       |
| 졸음     | 기준 대비 40% 넘게 감긴 상태가 1초 내내 이어진 초가 **4초 이상 연속** (슬롯 경계를 넘어 이어서 셈) | 이탈       |
| 딴짓     | 명확한 딴짓(유튜브 게임·엔터 영상, SNS·OTT·커뮤니티 등 [딴짓 사이트](docs/딴짓_사이트_목록.md))이 3초 이상, 딴짓 영상 백그라운드 재생 5초 이상, 또는 LLM이 딴짓으로 분류 | 이탈       |
| 집중     | LLM이 작업 창으로 분류                                                                             | 집중       |
| 미분류   | 그 외                                                                                              | 분모 제외  |

**집중도 = 집중 시간 ÷ (집중 + 자리비움 + 졸음 + 딴짓 시간) × 100.** 짧은 이탈도 보정 없이 그대로 세고(유예 보정은 11-09 폐기), 눈 깜빡임은 점수에 넣지 않고 참고 지표로만 보여줍니다. 판정된 시간이 너무 짧으면 점수 대신 "판정 데이터 부족"을 표시합니다. 자세한 규칙은 [docs/FocusPomo_집중도_점수_산출_명세.md](docs/FocusPomo_집중도_점수_산출_명세.md)에 있습니다.

임계값은 모두 임시값이며 `config/`에서 관리하고, 자체 라벨링 검증 후 튜닝합니다.

## 기술 스택

| 구분           | 사용 기술                                                 |
| -------------- | --------------------------------------------------------- |
| 언어·환경      | Python **3.12.10**, venv, Windows 10/11                   |
| GUI            | PySide6                                                   |
| 얼굴·눈 인식   | OpenCV, MediaPipe Face Landmarker (Tasks API)             |
| 활성 창 추적   | pywin32, psutil, pywinauto (브라우저 도메인 추출 검증 중) |
| 창 분류·리포트 | LLM API — Gemini 무료 티어 기본, Groq로 바꿀 수 있음 (OpenAI 호환 JSON 모드, 세션 종료 시 분류 1회 + 문구 1회) |
| 데이터 저장    | 로컬 JSON / JSONL                                         |

Docker·WSL·클라우드는 사용하지 않습니다.

## 시작하기

자세한 설치 과정은 **[개발환경 설정 가이드](docs/개발환경_설정가이드.md)** 를 참고하세요. 요약하면:

```powershell
# 1. clone (경로에 한글·공백이 없는 위치 권장)
cd C:\dev
git clone https://github.com/<OWNER>/focuspomo.git
cd focuspomo

# 2. 가상환경 생성 및 활성화
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1

# 3. 패키지 설치
python -m pip install --upgrade pip
pip install -r requirements.txt

# 4. 설치 확인
python -c "import cv2, mediapipe, PySide6, win32gui; print('OK')"

# 5. 실행
python main.py
python main.py --data-dir C:\temp\fp-data   # 개발 중 기록을 다른 폴더에 저장
python main.py --no-youtube                 # 유튜브 카테고리 조회 끄기 (기본은 켬, .env의 YOUTUBE_API_KEY 필요)
python main.py --no-llm                     # LLM 창 분류·문구 끄기 (기본은 켬, .env의 GEMINI_API_KEY 등 필요)
python main.py --camera 1                   # 다른 웹캠 번호

# 웹캠 없이 mock 카메라로 실행 (아래 옵션은 --mock-camera와 함께 줄 때만 동작)
python main.py --mock-camera
python main.py --mock-camera --scenario fail_twice      # mock 캘리브레이션 시나리오
python main.py --mock-camera --no-camera                # mock 웹캠을 열지 못한 상태
python main.py --mock-camera --camera-lost-after 8      # mock 웹캠이 8초 뒤 끊겼다가 5초 뒤 복구
```

- 웹캠 CV, 활성 창 추적, 점수(LLM 창 분류 포함)가 모두 실제로 연결되어 있습니다. 개발 중에는 `--data-dir`로 기록을 분리하세요.
- 세션이 끝나면 LLM 응답을 기다리는 동안(보통 몇 초, 최대 약 20초) "결과 정리 중"이 표시됩니다. 창은 멈추지 않습니다.
- LLM 키가 없거나 호출이 실패하면 웹캠 신호와 기본 딴짓 규칙만으로 점수를 내고(리포트에 안내 문구), 리포트 문구는 기본 문구로 대체합니다.
- `--scenario`, `--no-camera`, `--camera-lost-after`를 `--mock-camera` 없이 주면 무시되고 실제 웹캠이 켜집니다.
- 대기 화면에서 **추적 모드**를 고를 수 있습니다 (`data/settings.json`에 저장).
  - **웹캠 + 창** (기본): 웹캠과 활성 창으로 판정합니다.
  - **웹캠만**: 활성 창을 기록하지 않고 웹캠 신호(자리 이탈·졸음)로만 판정합니다. 창 목록은 LLM에 보내지 않습니다.
  - **창만**: 웹캠을 끄고(표시등 꺼짐) 캘리브레이션 없이 바로 시작합니다. 활성 창으로만 판정합니다.
  - **타이머만**: 웹캠과 창 추적 없이 타이머만 씁니다. 점수는 계산하지 않고 집중한 시간만 기록하며, LLM도 부르지 않습니다.
  - 웹캠을 끄는 모드에서 다시 웹캠 모드로 바꾸면 모델을 다시 불러오느라 "웹캠 준비 완료"까지 몇 초 걸립니다.
- 앱을 켜면 얼굴 검출 모델을 먼저 불러옵니다. 모델 준비와 웹캠 첫 프레임이 끝나야 "웹캠 준비 완료"가 되고 시작 버튼이 켜집니다 (처음 실행 시 10초 정도 걸릴 수 있음).
- 세션 중에 창을 닫으면 "저장하고 종료"를 확인한 뒤 "세션 종료" 버튼처럼 지금까지의 기록을 저장하고 닫습니다 (취소하면 세션 계속). 앱이 꺼질 때 웹캠과 추적 스레드를 정리합니다.

- Face Landmarker 모델(`models/face_landmarker.task`)은 레포에 포함되어 있어 따로 받을 필요가 없습니다.
- LLM API 키는 로컬 `.env`에 두고 **절대 커밋하지 않습니다.** `.env.example`을 `.env`로 복사해 `GEMINI_API_KEY`를 넣고(무료, https://aistudio.google.com/apikey), `python -m scoring.llm_client --check`로 연결을 확인하세요.
- 같은 이름의 환경변수가 있으면 `.env`보다 먼저 읽습니다. VS Code의 `python.terminal.useEnvFile`이 켜져 있으면 터미널을 열 때 `.env`가 환경변수로 들어가므로, `.env`를 고친 뒤에는 **새 터미널을 열어야** 반영됩니다 (`--check`에 나오는 `provider`로 확인).
- 웹캠이 열리지 않으면 Windows 설정 → 개인정보 → 카메라에서 데스크톱 앱 접근을 허용하세요.

## 프로젝트 구조

```
focuspomo/
├── main.py                   # 앱 진입점, 큐 생성, GUI·카메라 스레드·세션 워커 연결
├── schemas.py                # 공용 데이터 스키마 (TypedDict, enum, 헬퍼)
├── requirements.txt          # 패키지 버전 고정
├── docs/                     # 설정·협업 가이드, 개발계획서, 스키마 명세
├── models/
│   └── face_landmarker.task  # Face Landmarker 모델
├── config/
│   ├── scoring.py            # 집중도 점수 설정 (임시값)
│   ├── llm.py                # LLM 제공사·모델·타임아웃·재시도
│   ├── env.py                # .env에서 API 키 읽기
│   ├── window_rules.py       # 명확한 딴짓 유튜브 카테고리·딴짓 사이트 목록 (docs/딴짓_사이트_목록.md)
│   └── aggregation.py        # 캘리브레이션·감김·졸음·슬롯 압축 임계값 (임시값)
├── core/                     # GUI 없이 테스트하는 로직 (슬롯 병합, 카메라 명령·이벤트, 세션 워커, 세션 종료, 판정)
├── gui/                      # PySide6 화면 (대기, 캘리브레이션, 타이머, 미니 모드, 리포트)
├── cv_module/                # 캘리브레이션, 1초 요약, 10초 슬롯 압축
├── window_tracker/           # 활성 창 조회
├── scoring/                  # 집중도 점수 산출, LLM 창 분류·리포트 문구·폴백
├── storage/                  # 세션 결과·원본 기록 저장
├── mocks/                    # 모듈별 독립 개발용 mock 데이터
└── tests/                    # 단위 테스트, 자체 라벨링 검증
```

## 데이터와 프라이버시

- **웹캠 영상은 기기 밖으로 나가지 않습니다.** 원본 영상·프레임은 저장·전송되지 않습니다.
- 웹캠을 쓰는 추적 모드(웹캠 + 창, 웹캠만)에서는 앱이 켜져 있는 동안 웹캠이 열려 있어 표시등이 켜집니다. 프레임 분석은 캘리브레이션과 세션 중에만 합니다. 창만·타이머만 모드에서는 웹캠을 닫습니다.
- 웹캠만·타이머만 모드에서는 활성 창을 기록하지 않습니다. 웹캠만 모드의 LLM 호출은 리포트 문구(집계값) 하나뿐이고, 타이머만 모드는 LLM을 부르지 않습니다.
- 세션 종료 시 LLM API로 보내는 정보는 ① 창 분류: 세션에 나온 창 목록의 **앱 이름, 브라우저 도메인, 유튜브 카테고리, 등장 횟수**, ② 리포트 문구: **점수와 태그별 시간 같은 집계값, 딴짓 상위 항목·많이 쓴 창·오래 이어 쓴 구간의 앱 이름(또는 도메인)·유튜브 카테고리·사용 시간·시작 시점**뿐입니다. 얼굴·졸음 등 슬롯별 웹캠 신호, 창 제목 전체, URL 전체, 화면 내용, 키 입력, 눈 측정 수치는 보내지 않습니다.
- [딴짓 사이트 목록](docs/딴짓_사이트_목록.md)에 걸린 창과 FocusPomo 창은 로컬에서 판정하므로 ① 창 분류에는 보내지 않습니다. 다만 ② 리포트 문구에는 사용 시간 요약으로 이 창들의 앱 이름·도메인도 들어갑니다 (예: "youtube.com [Gaming] 12분").
- 기본 제공사인 Gemini API 무료 티어는 보낸 내용을 Google 제품 개선에 쓸 수 있습니다. 원하지 않으면 `--no-llm`으로 끄거나, 입력을 학습에 쓰지 않는다고 밝힌 Groq(`LLM_PROVIDER=groq`)를 쓰세요.
- 유튜브 카테고리 조회는 기본으로 켜져 있습니다 (게임·엔터 영상 같은 명확한 딴짓을 가리는 데 필요). 이때 시청 중인 영상 ID가 YouTube Data API로 전송되며, 영상 ID는 저장하지 않습니다. `--no-youtube`로 끄면 영상 ID를 보내지 않고, `.env`에 `YOUTUBE_API_KEY`가 없어도 카테고리 없이 동작합니다.
- 기록은 모두 로컬에 저장되며 앱 안에서 직접 확인·삭제할 수 있습니다.
  - `data/sessions.jsonl` — 세션 결과 (세션당 한 줄)
  - `data/focus_log/{session_id}.json` — 캘리브레이션, 1초 요약, 병합 슬롯 로그
- `data/`와 `.env`는 `.gitignore`에 등록되어 레포에 올라가지 않습니다.

## 협업 규칙 요약

- `main`에 직접 push하지 않고, `feature/<모듈>-<작업>` 브랜치에서 작업 후 PR로 merge합니다.
- 커밋 메시지: `<종류>(<모듈>): <요약>` — 예: `feat(cv): EAR 기반 1초 요약 생성`
- PR은 팀원 1명 이상 승인 후 **Squash and merge**.

자세한 내용은 [Git 협업 가이드](docs/Git_협업가이드.md)를 참고하세요.
