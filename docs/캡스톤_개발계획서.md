# FocusPomo 개발 계획서
### 산만함·졸음 인식 기반 집중 관리 뽀모도로 타이머 — 구현 계획 (v6)

> 이 문서는 `캡스톤_제안서_하이브리드버전.md`의 설계를 실제 개발 작업 단위로 구체화한 것입니다.
> **필드 이름·타입·enum 값은 [FocusPomo_데이터_스키마_명세_v1.md]이 기준입니다.** 이 문서와 명세가 다르면 명세를 따르고, 코드에서는 레포 루트의 `schemas.py`(TypedDict)로 정의합니다.
>
> v3 변경점: (1) 팀 전원 Windows 환경으로 통일되어 크로스플랫폼 전략 폐기, (2) MediaPipe Face Mesh → Face Landmarker로 교체, (3) 활성 창 추적을 이벤트 기반에서 주기 샘플링으로 통일하고 CV·창 데이터를 병합한 슬롯 로그 도입, (4) LLM 페이로드에 얼굴·졸음 신호까지 포함.
>
> v4 변경점: (1) CV는 1초 단위로 요약을 기록하고 10초 슬롯으로 압축하는 단계를 신설. (2) 활성 창은 10초 주기 조회를 유지. (3) 눈 깜빡임 검출을 위해 CV 스레드는 내부적으로 더 높은 프레임레이트로 처리하고 1초 요약만 만들도록 명시.
>
> v5 변경점: (1) 개발 환경 확정 — Python 3.12.10, venv, Face Landmarker 모델 파일 레포 포함, Docker/WSL·AWS 미사용 (0.1). (2) GUI 프레임워크를 PySide6로 확정.
>
> **v6 변경점**:
> (1) **데이터 스키마 통일** — 스키마 명세 v1 채택. 시점 필드 `timestamp`, 모든 슬롯 스키마에 `slot`, enum은 영문 키(`work`/`distraction`/`unknown` 등) + GUI 한글 매핑, `session_id`는 `YYYYMMDD-HHMMSS` 등 (2장 전체, 9장 요약).
> (2) **슬롯 압축을 세션 중 실시간으로** — CV 스레드가 1초 요약을 10초마다 압축해 GUI로 보내고, 창 스레드도 10초마다 GUI로 보낸다. 두 스레드는 같은 큐(`slot_queue`)를 쓰고 GUI가 하나의 슬롯 로그로 관리한다 (1장, 2.6).
> (3) **졸음 판정을 PERCLOS 평균 → 임계값 + 4초 연속 방식으로** — 개인 기준 대비 눈이 임계값 넘게 감긴 상태가 1초 내내 이어진 초를 세고, 이것이 슬롯 경계를 넘어서도 4초 이상 연속되면 졸음 (2.1, 2.6).
> (4) **세션 시작 캘리브레이션** — 세션마다 5초 동안 화면을 응시하게 해 개인별 눈 크기 기준값(`ear_baseline`)을 잡는다. 25분 타이머는 캘리브레이션이 끝난 뒤 시작한다 (2.0).

## 1. 전체 아키텍처

**단일 프로세스, 멀티스레드** 구조로 통합한다.

```
FocusPomo (단일 Python 프로세스)
├── Main Thread (GUI, PySide6)
│     · 세션 시작 → 캘리브레이션 화면(5초 응시) → 끝난 시각을 session_start로 두 스레드에 공유
│     · QTimer로 slot_queue를 비우며 CvSlot·WindowSlot을 slot 번호로 병합 → 세션 슬롯 로그(MergedSlot) 관리
│     · 세션 종료 시 슬롯 로그를 점수 모듈에 넘기고, 결과(SessionResult)를 리포트 화면에 렌더링·저장
├── CV Thread
│     · 캘리브레이션: 응시 구간 EAR 중앙값 → ear_baseline
│     · 세션 중: 웹캠 ~15fps 처리 → 1초마다 CvSecond 생성(내부 보관)
│     · 10초마다 CvSecond 10개를 CvSlot으로 압축해 slot_queue에 push (1초 원본도 함께 첨부)
├── Window Thread
│     · session_start + 10*k 시각마다 활성 창 조회 → WindowSlot을 slot_queue에 push
└── (세션 종료 시) Score 호출
        (1) 병합 슬롯 로그의 일부 필드만 LLM API로 전달 → 창 분류 + 리포트 문구만 받음 (2.7)
        (2) 코드에서 가중치 공식(2.5)으로 점수를 결정론적으로 계산
```

- **큐는 하나**: CV·창 스레드는 모두 10초 슬롯 단위 메시지를 같은 `queue.Queue`(`slot_queue`)에 넣는다. 메시지는 `source`(`"cv"` / `"window"`)로 구분한다 (2.6).
- **GUI 위젯은 메인 스레드에서만** 건드린다. 스레드는 큐에 쓰기만 하고, GUI가 읽어서 슬롯 로그와 화면을 갱신하는 단방향 흐름을 지킨다.
- **시간 기준 통일**: 모든 값은 `time.time()` 기반 `timestamp`를 갖고, 슬롯 번호는 항상 `slot = int((timestamp - session_start) // 10)`로 계산한다 (`schemas.slot_index`). 창 스레드는 `sleep(10)` 반복 대신 `session_start + 10*k` 시각에 맞춰 다음 조회 시각을 매번 계산한다.
- **도착 순서**: 슬롯 k의 창 메시지는 슬롯 시작 시점에, CV 메시지는 슬롯이 끝난 뒤에 도착한다. GUI는 먼저 온 쪽으로 슬롯을 만들고 나중 것을 채운다.

## 2. 모듈별 상세 설계 및 인터페이스

병렬 개발이 가능하도록 스키마를 스키마 명세 v1로 먼저 고정하고, 각자 이 형태의 mock 데이터로 독립 개발 후 2주차(6장)에 실제 모듈로 교체한다. 아래 필드 표는 요약이며, 전체 정의는 명세를 따른다.

### 2.0 캘리브레이션 (김시언 — CV 스레드, GUI 화면은 김민서)

세션 시작 버튼을 누르면 GUI가 "화면을 5초간 바라봐 주세요" 화면을 띄우고, CV 스레드가 그동안 얼굴이 검출된 프레임의 EAR 중앙값을 `ear_baseline`으로 잡는다. 평균 대신 중앙값을 쓰는 이유는 응시 중 깜빡임의 영향을 줄이기 위해서다. 매 세션 다시 측정하므로 조명·자세·안경 착용 변화에도 기준이 맞춰진다.

```python
Calibration = {
    "ear_baseline": float,
    "valid_frames": int,            # 얼굴이 검출된 프레임 수
    "face_detected_ratio": float,   # 0~1
    "started_at": float,
    "ended_at": float,              # = session_start
    "fallback_used": bool           # 실패로 직전 세션 기준값을 썼는지
}
```

- **타이머와의 관계**: 25분 타이머와 `session_start`는 캘리브레이션이 끝난 뒤 시작한다 (캘리브레이션 5초는 집중 시간에 포함하지 않음).
- **실패 처리**: `face_detected_ratio` < `CALIBRATION_MIN_FACE_RATIO`(임시 0.7)이면 응시를 한 번 더 요청한다. 다시 실패하면 직전 세션의 `ear_baseline`을 쓰고 `fallback_used=True`로 둔다. 직전 값도 없으면(첫 세션) 세션을 시작하지 않고 캘리브레이션을 다시 요구한다.

### 2.1 CV 모듈 (김시언) — 1초 요약 생성 (스레드 내부)

```python
CvSecond = {
    "timestamp": float,               # 해당 1초 구간의 시작 시각
    "face_present": bool,             # 그 1초 동안 처리한 프레임의 과반에서 얼굴 검출
    "eyes_closed": bool,              # 그 1초 동안 처리한 프레임이 모두 '감김'. 얼굴 없으면 False
    "blink_count": int,               # 그 1초에 끝난 짧은 감김(≤ BLINK_MAX_SEC) 수. 얼굴 없으면 0
    "ear_mean": float | None,         # 디버깅용. 얼굴 없으면 None
    "gaze_off_screen": bool | None    # 예약 필드, 미구현 동안 None
}
```

- 얼굴 랜드마크 추출은 **MediaPipe Face Landmarker**(Tasks API, `models/face_landmarker.task`)를 사용한다.
- **처리 프레임레이트**: 깜빡임은 0.1~0.4초 수준의 짧은 이벤트라, CV 스레드는 웹캠 프레임을 **약 15fps 이상**으로 처리하고 1초마다 요약 하나를 만든다. 처리 fps(임시 15)는 1주차 스탠드얼론 스크립트에서 CPU 부하를 보고 조정한다.
- **눈 감김·졸음 판정 (임계값 방식)** — 프레임마다 개인 기준 대비 감긴 정도를 계산한다.

  ```
  closure = 1 - EAR / ear_baseline
  ```

  1. `closure` > `CLOSURE_THRESHOLD`(임시 0.4, 즉 EAR이 기준의 60% 미만)인 프레임을 '감김'으로 본다.
  2. 1초 동안 모든 프레임이 감김이면 그 초는 `eyes_closed=True`다.
  3. 감김이 `BLINK_MAX_SEC`(임시 0.5초) 이하로 끝나면 깜빡임 1회로 센다 (프레임 단위).
  4. 졸음(슬롯 `drowsy`) 판정은 `eyes_closed`가 연속된 초 수로 한다 (2.6).
- **평균 비율(PERCLOS)은 쓰지 않는다.** v5까지의 `eyes_closed_ratio` 평균 방식을 폐기했다.
- **얼굴 미검출 시 규칙**: 얼굴이 없는 초는 `eyes_closed=False`, `blink_count=0`, `ear_mean=None`으로 채운다. 측정 불가를 졸음으로 오판해 자리 이탈과 이중 감점되는 것을 막는다.

### 2.2 활성 창 추적 모듈 (신명철) — 10초마다 `slot_queue`에 push

활성 창은 **10초 주기 폴링**으로 조회한다. 조회 주기가 슬롯 길이와 같아 슬롯당 샘플이 정확히 1개이므로 압축 없이 그대로 슬롯이 된다.

```python
WindowSlot = {
    "slot": int,              # 창 스레드가 slot_index(timestamp, session_start)로 직접 계산
    "timestamp": float,       # 조회 시각 (session_start + 10*k에 맞춰 조회)
    "app_name": str | None,   # 예: "VS Code", "Chrome". 조회 실패 시 None
    "domain": str | None      # 브라우저인 경우 도메인만 (예: "youtube.com"), 그 외·추출 실패 시 None
}
# 큐 메시지: {"source": "window", "slot": WindowSlot}
```

- `pywin32`로 활성 창 핸들과 제목은 쉽게 얻을 수 있지만, 브라우저의 **실제 방문 도메인**은 창 제목만으로는 얻기 어렵다. Windows UI Automation(`pywinauto`)으로 주소창 텍스트를 읽는 방법을 1주차에 스파이크로 검증하고, 안 되면 v1에서는 `domain`을 항상 `None`으로 두고 `app_name`만으로 분류한다 (8장).
- 시스템 창(잠금 화면, 작업 전환 UI 등)에서 조회가 실패하면 `app_name=None`으로 보낸다.
- **알려진 트레이드오프**: 10초에 한 시점의 창이 그 슬롯 전체를 대표한다. 검증(7장)에서 딴짓 판정이 지나치게 들쭉날쭉하면 슬롯 내 2~3회 조회 후 최빈값을 쓰는 방식으로 올린다.

### 2.3 집중도 점수 산출 모듈 (신명철) — 휴식 시작 시 1회 호출

**LLM의 역할은 "창 분류 + 리포트 문구 생성"으로 한정한다.** 점수(가감점 합산)는 코드에서 결정론적으로 계산한다.

**입력**: GUI가 세션 동안 관리한 병합 슬롯 로그(`list[MergedSlot]`, 2.6) + `Calibration`. v6부터 압축은 세션 중에 이미 끝나 있으므로 이 모듈에는 압축 단계가 없다.

**처리 순서**:
1. 병합 슬롯 로그에서 LLM용 필드만 골라(2.7) LLM API에 전달하고, 슬롯별 `window_label`과 `report_text`를 받는다.
2. 반환된 `slot_labels`를 슬롯 로그와 `slot` 번호로 매칭한다. 응답에서 빠진 슬롯이나 정의되지 않은 값은 `unknown`으로 처리한다.
3. 2.5 공식으로 슬롯별 `score`를 계산하고 합산해 `score_total`을 낸다.
4. 슬롯별 대표 태그 `final_tag`를 우선순위(2.7)로 파생해 리포트 표에 쓴다.

**출력** (GUI가 그대로 받아 렌더링·저장하는 최종 스키마):

```python
SessionResult = {
    "schema_version": 1,
    "session_id": str,             # "YYYYMMDD-HHMMSS"
    "session_start": float,        # = 캘리브레이션 종료 시각
    "session_end": float,          # 중간 종료 포함
    "ear_baseline": float,
    "slot_scores": [
        {"slot": int, "start": float, "end": float,
         "window_label": "work" | "distraction" | "unknown",
         "final_tag": "away" | "drowsy" | "distraction" | "focus" | "unknown",
         "blink_count": int, "score": int},
        ...
    ],
    "score_total": int,
    "blink_bonus_total": int,      # 캡 적용 후 깜빡임 가점 합
    "drowsy_count": int,           # 졸음 감점 슬롯 수
    "away_count": int,             # 자리 이탈 감점 슬롯 수
    "distraction_count": int,      # 딴짓 감점 슬롯 수
    "report_text": str,            # LLM 문구 또는 폴백 문구
    "llm_call_failed": bool
}
```

- `llm_call_failed=True`이면 모든 슬롯의 `window_label`을 `unknown`으로 두어 딴짓 감점을 적용하지 않고, 깜빡임·졸음·자리 이탈만으로 계산한다. `report_text`는 "이번 세션은 웹캠 신호만으로 계산되었습니다" 같은 폴백 문구로 대체한다.

### 2.4 GUI/통합 (김민서)

- **PySide6** 기반으로 구현한다.
- **캘리브레이션 화면**: 세션 시작 시 5초 응시 안내 → CV 스레드의 `Calibration` 결과를 받아 성공/재시도/폴백을 처리 → `session_start`를 확정해 두 스레드에 공유하고 25분 타이머를 시작한다.
- **슬롯 로그 관리**: QTimer로 `slot_queue`를 주기적으로 비우며 `source`에 따라 CvSlot·WindowSlot을 `slot` 번호 기준 MergedSlot에 채운다. CvSlotMessage에 첨부된 1초 원본(`seconds`)은 focus_log 저장용으로 따로 모은다. 병합 로직은 `core/slot_log.py`로 분리해 GUI 없이 단위 테스트한다.
- **세션 종료**: CV 스레드의 마지막 슬롯 flush를 잠깐(임시 2초) 기다린 뒤, 끝내 한쪽 메시지가 오지 않은 슬롯을 기본값으로 채우고(2.6) 점수 모듈(2.3)을 호출한다.
- **리포트 화면**: `SessionResult`를 렌더링한다. enum은 `schemas.WINDOW_LABEL_KO`, `schemas.FINAL_TAG_KO`로 한글 표시한다.
- **로컬 저장**(3장)도 이 계층에서 담당한다.
- `score_total`을 원점수로 보여줄지, 백분율/등급으로 변환할지는 8장의 열린 질문.

### 2.5 집중도 점수 산출 공식

네 가지 신호를 **10초 슬롯** 단위로 가감점 처리한다. **작업 창 사용은 중립(0)**이며, 감점은 딴짓 창 사용에만 적용한다.

| 신호 | 판정 조건 | 방향 | 임시 가중치 |
|---|---|---|---|
| 눈 깜빡임 | 슬롯 `blink_count` | 가점만 | 1회당 +1, 슬롯당 최대 +3 |
| 졸음 | 슬롯 `drowsy is True` (2.6) | 감점 | -2 |
| 얼굴 화면 이탈 | 슬롯 `face_present is False` (2.6) | 감점 | -2 |
| 활성 창 — 딴짓 | `window_label == "distraction"` | 감점 | -1 |
| 활성 창 — 작업/미분류 | `window_label in ("work", "unknown")` | 중립 | 0 |

가중치는 **모두 임시값**이며 7장의 자체 라벨링 검증 후 튜닝한다. 코드에서는 설정 파일로 분리한다:

```python
# config/scoring_weights.py — 임시값, 검증 후 튜닝 예정
WEIGHTS = {
    "blink_bonus_per_blink": 1,
    "blink_bonus_cap": 3,       # 슬롯당 최대 깜빡임 가점
    "drowsy_penalty": 2,
    "face_away_penalty": 2,
    "distraction_penalty": 1,
}
```

```python
def slot_score(slot: MergedSlot, window_label: WindowLabel, weights=WEIGHTS) -> int:
    score = 0
    score += min(slot["blink_count"], weights["blink_bonus_cap"]) * weights["blink_bonus_per_blink"]
    if slot["drowsy"]:
        score -= weights["drowsy_penalty"]
    if slot["face_present"] is False:      # None(측정 불가)은 감점하지 않음
        score -= weights["face_away_penalty"]
    if window_label == "distraction":
        score -= weights["distraction_penalty"]
    return score
```

- 얼굴 이탈과 졸음은 같은 슬롯에서 동시에 감점되지 않는다 (`face_present`가 `True`가 아니면 `drowsy=False`).
- 딴짓 감점과 졸음/이탈 감점은 서로 다른 채널이므로 한 슬롯에서 동시에 발생할 수 있다 (예: 졸면서 유튜브 창이 떠 있으면 -2-1 = -3).

### 2.6 CV 10초 슬롯 압축 및 슬롯 로그 병합

**압축은 CV 스레드가 세션 중에 10초마다 한다** (v5의 "세션 종료 후 일괄 압축"에서 변경). 25분 세션이면 1,500개의 1초 요약이 150개 슬롯으로 GUI에 전달된다.

```python
CvSlot = {
    "slot": int,
    "timestamp": float,              # session_start + 10*slot
    "face_present": bool | None,
    "drowsy": bool,
    "closed_run_max": int,           # 이 슬롯 안에서 closed_run의 최댓값 (앞 슬롯에서 이어진 값 포함)
    "blink_count": int,
    "ear_mean": float | None,
    "gaze_off_screen": bool | None   # 예약
}
# 큐 메시지: {"source": "cv", "slot": CvSlot, "seconds": list[CvSecond]}
```

| 슬롯 필드 | 압축 규칙 | 임시 파라미터 |
|---|---|---|
| `face_present` | 슬롯 내 `face_present=True`인 초의 비율이 기준 이상이면 True, 미만이면 False. 1초 요약이 0개면 None | `FACE_PRESENT_MIN_RATIO = 0.5` |
| `drowsy` | 아래 연속 감김 규칙. `face_present`가 True가 아니면 무조건 False | `DROWSY_MIN_RUN_SEC = 4` |
| `closed_run_max` | 슬롯 안의 각 초에서 본 `closed_run`의 최댓값 | — |
| `blink_count` | 1초 요약 `blink_count`의 합 (캡은 점수 단계에서 적용) | — |
| `ear_mean` | 1초 `ear_mean`들의 평균 (디버깅용) | — |

**연속 감김 기반 졸음 규칙**
1. CV 스레드는 `eyes_closed=True`가 연속된 초 수 `closed_run`을 센다.
2. `closed_run`은 **슬롯이 바뀌어도 초기화하지 않고** 이어서 센다. `eyes_closed=False`인 초나 얼굴이 없는 초가 오면 0으로 되돌린다.
3. 슬롯 안의 어느 초에서든 `closed_run` ≥ `DROWSY_MIN_RUN_SEC`이면 그 슬롯은 `drowsy=True`다.

- 2번 덕분에 경계에 걸친 졸음(예: 앞 슬롯 8~9초 + 다음 슬롯 0~1초)도 다음 슬롯에서 잡힌다. 슬롯 안에서만 세면 6초를 졸아도 3+3초로 나뉘어 놓칠 수 있다.
- 1초 단위로 세므로 실제로는 4~5초 이어진 감김부터 졸음으로 판정된다 (감수).
- 한 프레임만 눈 뜬 것으로 튀어도 그 초가 `eyes_closed=False`가 되어 연속이 끊긴다. 검증에서 졸음을 너무 놓치면 `eyes_closed` 기준을 "프레임의 90% 이상 감김"처럼 완화한다 (8장).

**판정 파라미터** (`config/aggregation.py`, 모두 임시값)

| 상수 | 임시값 | 의미 |
|---|---|---|
| `CALIBRATION_SEC` | 5 | 캘리브레이션 응시 시간(초) |
| `CALIBRATION_MIN_FACE_RATIO` | 0.7 | 캘리브레이션 성공 최소 얼굴 검출 비율 |
| `CLOSURE_THRESHOLD` | 0.4 | 기준 대비 이만큼 넘게 감기면 '감김' |
| `BLINK_MAX_SEC` | 0.5 | 이하로 끝난 감김 = 깜빡임 |
| `DROWSY_MIN_RUN_SEC` | 4 | `eyes_closed=True`가 이만큼 연속되면 졸음 |
| `FACE_PRESENT_MIN_RATIO` | 0.5 | 슬롯에서 얼굴 있음으로 볼 최소 초 비율 |

**GUI 병합 규칙 (MergedSlot = CvSlot 필드 + `app_name`, `domain`)**
- 같은 `slot` 번호의 CV 메시지와 창 메시지를 한 줄로 합친다. 도착 순서는 상관없다.
- 같은 슬롯의 창 메시지가 두 번 오면(타이밍 지터) 나중 메시지로 덮어쓴다.
- 세션 종료 시 한쪽 메시지가 오지 않은 슬롯은 기본값으로 채운다 — CV 쪽: `face_present=None`, `drowsy=False`, `closed_run_max=0`, `blink_count=0`, `ear_mean=None` / 창 쪽: `app_name=None`, `domain=None`. `None`은 "측정 불가"이므로 감점하지 않는다.

**예외 처리 (CV 스레드 압축)**
- **1초 요약 누락**: 스레드 지연 등으로 슬롯 안의 1초 요약이 10개보다 적으면 있는 것만으로 비율을 계산한다 (분모는 실제 개수). 빠진 초는 `closed_run`을 끊는 것으로 본다.
- **마지막 슬롯이 10초 미만**: 세션이 중간에 끝나면 CV 스레드가 남은 초만으로 압축해 바로 보낸다(flush).

### 2.7 LLM 요청/응답 형식

세션 종료 시 병합 슬롯 로그에서 아래 필드만 골라 LLM API에 한 번에 전달한다. `blink_count`, `closed_run_max`, `ear_mean`, `gaze_off_screen`과 CV 1초 원본은 보내지 않는다.

```python
# LLM 입력 (LlmSlotInput 리스트)
[
    {"slot": 0, "timestamp": 1790753400.0, "app_name": "VS Code", "domain": None,
     "face_present": True, "drowsy": False},
    ...
]
```

- 얼굴·졸음 신호까지 함께 보내는 이유는 `report_text`가 "졸린 상태에서 유튜브를 보고 있었다"처럼 여러 신호를 종합해 요약하도록 하기 위함이다. `face_present`가 `None`인 슬롯은 `null`로 전달한다.
- **프라이버시 원칙 갱신 필요**: 제안서 5장은 "창 제목만 전송"이지만, 얼굴 존재·졸음 여부라는 **파생 이진값**도 외부로 전송된다. 웹캠 원본 영상·프레임은 여전히 로컬을 벗어나지 않는다. 제안서 5장 문구를 함께 갱신해야 한다.

```python
# LLM 출력 (JSON 모드)
{
    "slot_labels": [{"slot": 0, "window_label": "work" | "distraction" | "unknown"}, ...],
    "report_text": str   # 한국어 1~3문장
}
```

- LLM은 라벨과 리포트 문구만 반환한다. 점수는 2.5 공식으로 코드가 계산한다.
- **최종 태그(`final_tag`) 우선순위** — 여러 조건이 동시에 참이어도 표시는 하나만, 점수는 2.5대로 모두 반영:

| 우선순위 | 값 | GUI 표시 | 조건 |
|---|---|---|---|
| 1 | `away` | 이탈(자리비움) | `face_present is False` |
| 2 | `drowsy` | 이탈(졸음) | `drowsy is True` |
| 3 | `distraction` | 이탈(딴짓) | `window_label == "distraction"` |
| 4 | `focus` | 집중 | `window_label == "work"` |
| 5 | `unknown` | 미분류 | 그 외 |

## 3. 데이터 저장 설계 (로컬 JSON/JSONL)

- **세션 결과**: `data/sessions.jsonl` — 세션마다 `SessionResult`(2.3) 한 줄씩 append.

```json
{"schema_version": 1, "session_id": "20260923-153000", "session_start": 1790753400.0, "session_end": 1790754900.0, "ear_baseline": 0.29, "score_total": 42, "blink_bonus_total": 18, "drowsy_count": 2, "away_count": 1, "distraction_count": 3, "report_text": "...", "llm_call_failed": false, "slot_scores": [...]}
```

- **세션별 원본 기록**: `data/focus_log/{session_id}.json` (`FocusLogFile`)

```python
FocusLogFile = {
    "schema_version": 1,
    "session_id": str,
    "session_start": float,
    "calibration": Calibration,        # 2.0
    "cv_seconds": list[CvSecond],      # CvSlotMessage의 seconds를 이어 붙인 1초 원본 (25분 기준 약 1,500개)
    "merged_slots": list[MergedSlot]   # 병합 슬롯 로그 (150개)
}
```

- `session_id`는 파일명으로도 쓰이므로 Windows에서 쓸 수 없는 콜론(`:`)을 넣지 않는다 (`YYYYMMDD-HHMMSS`).
- 제안서 5장의 프라이버시 원칙에 따라 사용자가 기록을 직접 확인·삭제할 수 있어야 하므로, 앱 내 "기록 삭제" 기능은 `data/focus_log/`와 `sessions.jsonl`을 대상으로 한다.
- CV 1초 원본은 임계값 튜닝과 라벨링 검증(7장)에서 슬롯 판정 원인을 되짚는 데 필요하므로 저장을 기본으로 한다 (25분 기준 1,500행 수준이라 용량은 작다).
- `schema_version`은 필드가 바뀌면 +1 하고, 통계 화면은 버전별로 읽기를 분기한다.
- 중첩 구조(`slot_scores` 등)가 있어 CSV 대신 JSON/JSONL을 쓴다. 통계 화면에서 집계할 때만 pandas 등으로 가공한다.

## 4. LLM API 연동 설계 (초안 — 팀 확정 필요)

### 4.1 프롬프트 설계 방향
- **입력 범위**: `LlmSlotInput` 리스트(앱·도메인·얼굴·졸음, 2.7). `blink_count`, `closed_run_max`, CV 1초 원본은 제외한다.
- **출력 범위**: 각 슬롯을 `work`/`distraction`/`unknown`으로 분류, 리포트 문구 생성. 두 가지뿐이다.
- structured output / JSON mode를 사용하고, 응답은 `schemas.LlmResponse` 형태로 검증한다. 정의되지 않은 라벨이나 빠진 슬롯은 `unknown`으로 처리한다.
- 창 제목·도메인은 전송하되 URL 전체(쿼리 파라미터 등)·본문 내용·키 입력은 전송하지 않는다.

### 4.2 아직 팀에서 정해야 할 것
- 사용할 LLM API 제공사·모델 (비용/응답속도/한국어 처리 품질 비교)
- 폴백 조건: 타임아웃 기준, 재시도 횟수
- `score_total` 표시 형식 (원점수/백분율/등급)
- 브라우저 도메인 추출 방식 (UI Automation vs 창 제목 파싱 vs `domain` 생략)

## 7. 검증 계획

- **캘리브레이션 안정성**: 같은 사람이 조명·거리를 바꿔 여러 번 캘리브레이션해 `ear_baseline` 편차를 본다. 안경 착용·미착용도 포함한다.
- **CV 모듈 정확도**: 팀원들이 "집중"과 "졸음(눈 감고 5초 이상 유지 등)/산만" 상태를 의도적으로 재현하며 타임스탬프를 기록 → 10초 슬롯 판정과 비교해 정밀도/재현율 산출. 어긋난 슬롯은 저장된 1초 원본으로 원인을 추적한다.
- **졸음 경계 케이스**: 슬롯 경계에 걸치도록 4~6초 눈 감기를 재현해, `closed_run` 이어 세기가 제대로 동작하는지 확인한다. 3초 감김은 졸음으로 잡히지 않아야 한다.
- **눈 깜빡임 검출 확인**: 정해진 시간 동안 깜빡임을 직접 세고 알고리즘의 `blink_count` 합과 비교한다. 처리 fps(2.1)를 정하는 근거로도 쓴다.
- **임계값 튜닝**: `CLOSURE_THRESHOLD`, `BLINK_MAX_SEC`, `DROWSY_MIN_RUN_SEC`, `FACE_PRESENT_MIN_RATIO`를 라벨링 결과와 비교해 조정한다. 졸음을 자주 놓치면 `eyes_closed` 기준 완화(프레임 90% 이상)를 먼저 검토한다.
- **LLM 창 분류 정확도**: 작업용·딴짓용 앱을 섞은 슬롯 로그 샘플로 LLM 분류와 사람 라벨을 비교한다.
- **창 샘플 대표성 확인**: "슬롯 안에서 작업 창과 딴짓 창을 오가는" 구간을 포함해 10초 1회 조회의 흔들림을 본다.
- **가중치 검증/튜닝**: 라벨링의 실제 집중/산만 여부와 `score_total`의 상관관계를 비교해 임시 가중치를 조정한다.
- **통합 테스트**: 웹캠 미검출, 캘리브레이션 실패, 창 조회 실패, 큐 메시지 순서 뒤바뀜·누락, 세션 중간 종료, LLM 타임아웃 각각에서 기본값 채우기·폴백이 정상 동작하는지 확인한다.

## 9. 원 제안서 대비 변경/구체화 사항 요약

- 역할 분담을 반영해 집중도 점수 산출 모듈을 신명철 담당으로 명시하고, GUI/통합(김민서)은 이 모듈의 출력을 받아 렌더링하는 구조로 조정.
- 각 모듈의 입출력 스키마를 구체적인 Python dict 형태로 고정해 병렬 개발이 가능하도록 함.
- 점수 산출 방식을 "LLM이 통째로 판정"에서 "신호별 가감점 공식(2.5)"으로 구체화하고, LLM의 역할은 창 분류·리포트 문구 생성으로만 한정.
- **(v3)** 팀 전원 Windows로 통일해 `pywin32` 직접 사용. MediaPipe Face Mesh → Face Landmarker. 활성 창 추적을 주기 샘플링으로 통일하고 병합 슬롯 로그 도입. LLM 페이로드에 얼굴·졸음 이진 신호 추가 (제안서 프라이버시 문구 갱신 필요).
- **(v4)** CV 1초 요약 + 10초 슬롯 압축 도입. 깜빡임 검출을 위해 CV 스레드는 ~15fps로 처리.
- **(v5)** 개발 환경(Python 3.12.10, venv, 모델 파일 레포 포함, Docker/WSL·AWS 미사용)과 GUI 프레임워크(PySide6) 확정.
- **(v6) 스키마 표기 통일**: 스키마 명세 v1 채택. 주요 변경 — `t` → `timestamp`, 모든 슬롯 스키마에 `slot`, `ear_value` → `ear_mean`, `slot_score` → `score`, `total_score` → `score_total`, `face_away_count` → `away_count`, 라벨·태그를 영문 enum 키로(GUI에서 한글 매핑), `schema_version`·`session_start`·`session_end`·`ear_baseline` 추가, `session_id`를 `YYYYMMDD-HHMMSS`로(Windows 파일명 호환), `sessions.jsonl`에 `llm_call_failed` 포함.
- **(v6) 실시간 슬롯 전달**: 압축을 세션 종료 후 일괄 처리에서 세션 중 CV 스레드의 10초 주기 처리로 옮기고, CV·창 스레드가 같은 `slot_queue`로 10초 슬롯을 보내 GUI가 하나의 슬롯 로그로 관리. 이에 따라 `slot_aggregator.py`를 `cv_module/slot_compressor.py`와 `core/slot_log.py`로 분리.
- **(v6) 졸음 판정 변경**: PERCLOS 평균 방식을 폐기하고, 개인 기준 대비 `closure` > `CLOSURE_THRESHOLD`인 상태가 1초 내내 이어진 초(`eyes_closed`)를 슬롯 경계를 넘어 이어 세어 4초 이상이면 졸음으로 판정.
- **(v6) 세션 시작 캘리브레이션**: 세션마다 5초 화면 응시로 `ear_baseline`을 측정하고, 25분 타이머는 그 뒤에 시작. 실패 시 재시도 → 직전 세션 값 폴백.
